CLAUDE.md and memory: teach Claude once, reuse forever

What CLAUDE.md is, where it lives, what to put in it (and what never to), how auto memory differs, and how Projects in the Claude app do a similar job.

Reading level

Every new Claude Code session starts with a fresh desk. Anthropic's memory documentation says it plainly: each session begins with a fresh context window, and two mechanisms carry knowledge across sessions. One you write (CLAUDE.md). One Claude writes for itself (auto memory). This part covers both, plus the closest thing in the Claude chat app (Projects). Plain pictures first, expert details in the panels.

What CLAUDE.md is

In plain words

CLAUDE.md is a note you leave for Claude on the desk before every working day: "here is how we do things here". It is just a text file in Markdown.

When should you add something? Anthropic's guidance is to treat CLAUDE.md as the place you write down what you would otherwise re-explain:

Expert viewHow the files combine

Anthropic's documentation says Claude Code loads CLAUDE.md and CLAUDE.local.md from the current working directory and every directory above it. All discovered files are concatenated into context rather than overriding each other, ordered from the filesystem root down to your working directory, so instructions closest to where you launched Claude are read last. Files in subdirectories below the working directory are not loaded at launch; each loads once Claude reads, writes or edits a file in that subdirectory.

Block-level HTML comments (<!-- notes for maintainers -->) are stripped before injection, so you can leave notes for humans without spending context. To skip other teams' files in a large monorepo, the docs describe a claudeMdExcludes setting. --add-dir directories are not loaded by default; an environment variable (CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1) turns that on.

What to put in it

Careful

Never put passwords, API keys or private data in CLAUDE.md. It is a plain file, usually committed to a shared repository, and it is loaded into every session.

Expert viewWriting instructions that stick

Anthropic's guidance: write instructions concrete enough to verify; target under 200 lines per CLAUDE.md file, because longer files consume more context and reduce adherence; use headers and bullets; and avoid contradictions, since Claude may pick one arbitrarily. @path/to/file imports let you split a file but do not reduce its context cost, because imported files also load at launch (recursive imports go up to four hops). For instructions that matter only for part of the codebase, use .claude/rules/ files, optionally scoped with paths: frontmatter so they load only when Claude works with matching files.

Claude treats CLAUDE.md as context, not enforced configuration. The documentation says to block an action reliably with a PreToolUse hook instead. Useful commands: /init generates a starting file from your codebase, /memory opens your memory files, and /doctor prompt-audit (requires v2.1.283 or later) checks instruction files for outdated or conflicting content. If your repository uses AGENTS.md instead, the docs describe how Claude Code can read it in place of CLAUDE.md.

Auto memory: notes Claude writes itself

Expert viewAuto memory details

Per Anthropic's memory page, auto memory records four kinds of notes (user, feedback, project and reference) and skips anything derivable from the codebase or already in CLAUDE.md. Files live under ~/.claude/projects/<project>/memory/. The first 200 lines or 25KB of MEMORY.md, whichever comes first, load at the start of every conversation; detailed topic files are read on demand. A CLAUDE.md file up to 4 MiB loads in full, but shorter files give better adherence. Subagents do not inherit the main conversation's auto memory, except a fork. You can audit and edit memory with /memory.

The chat-app cousin: Projects

If you use Claude in the browser or the app, Projects do a similar job. Anthropic's support pages describe a project as a self-contained workspace with its own chat history and knowledge base. Project instructions apply to every chat in the project, and files in the knowledge base are reused across chats.

Expert viewLimits worth knowing

The support article says chats inside a project do not share context with each other unless the information is in the knowledge base; the project name and description are not visible to Claude; and on a paid plan, when knowledge nears the context limit, Claude turns on retrieval (RAG) mode to expand capacity. Anthropic's pricing page lists Projects among Pro features and memory among Free features. Plan availability changes, so check your plan.

Write down once what you would otherwise explain every time.

Glossary
CLAUDE.md
A Markdown file of standing instructions that Claude Code reads at the start of every session.
Auto memory
Notes Claude Code writes for itself across sessions.
Rules
Topic files in .claude/rules/, optionally scoped to file paths.
Import
An @path line that pulls another file into context.
Project
A workspace in the Claude app with instructions and knowledge files.
Hook
A script that runs on an event; unlike CLAUDE.md it can enforce a rule.

Frequently asked questions

Is CLAUDE.md a guarantee?

No. It is context that Claude follows as well as it can. Use a hook to enforce something every time.

How long should it be?

Under about 200 lines. Move rarely needed material into rules or skills.

Can I keep personal preferences out of the shared file?

Yes. Use ~/.claude/CLAUDE.md for all projects, or CLAUDE.local.md for one project, and keep the local file out of git.

Key takeaways

  • CLAUDE.md is a plain file Claude Code reads at the start of every session
  • Keep it short, concrete and free of secrets
  • Commit it to the repo so the whole team shares it
