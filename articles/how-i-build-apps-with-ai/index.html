How I build small Android apps with AI assistance

A first-person, honest account of designing, building, testing and preparing 24 small offline Android apps with AI tools, what the AI does well and badly, and why a human still reviews everything.

  • Tests and review matter more as speed rises

Reading level

In my own time I design and prepare small Android apps for everyday jobs: shops, homes, families and kids. There are 24 so far, prepared end to end and being readied for Google Play. I use AI-assisted development and agents to build them. This is an honest description of how that works, written for curious people and not only engineers. Each section has a picture first and an Expert view with the working details.

The idea: small apps that do one job

Each app does a single, ordinary job: keeping records for a salon, tracking warranties, helping a child practise times tables, planning household chores. Small scope means each app can be finished, tested and explained in plain words. That is the first design decision, and it is mine, not the AI's.

Design rule one: the data stays on the phone

Every app stores its data on the phone itself. There is no account to create, no server of mine holding your records, no advertising and no analytics.

Expert viewPrivacy as a design constraint

Designing around privacy from the start makes the paperwork honest: each app has a plain privacy policy, and the store's data-safety answers match what the app really does. Practical rules I apply: storage stays in app-private locations, optional features that touch the network are opt-in and explained, text recognition and similar processing runs on the phone, and no analytics or advertising SDKs are included. It also reduces risk: data that is never collected cannot be breached.

My role and the AI's role

In plain words

Think of the AI as a very fast junior team that never gets tired, and needs clear direction and careful review. It does not own the product. I do.

The pipeline: from idea to a release-ready app

Expert viewWhy a written specification first

A specification gives the AI something precise to build against and gives me something to review the result against. Without it, an agent fills the gaps with plausible guesses, and plausible guesses are exactly how subtle bugs ship. In practice the spec lists screens, the behaviour of each control, validation rules, empty states and what the app deliberately does not do. Work then proceeds in small batches so a wrong turn is cheap to undo.

Testing is where the quality comes from

AI can write code quickly, and it can write wrong code quickly. So the safety net matters more, not less.

The faster code is produced, the more you need tests and review.

Expert viewReading tests, not only running them

An agent asked to make tests pass may find a way that hides a problem, for example by loosening an assertion. So I read the tests as well as the results. Edge cases worth insisting on: empty input, very large values, dates around month ends and time-zone changes, repeated taps, rotating the screen, and restoring from a backup. Stress testing with random input finds crashes that careful hand-written cases miss.

What AI does well, and what it does badly

Careful

AI-written code is not trustworthy because it looks tidy. I treat every change as untrusted until it has been read and tested.

Tools I use

Expert viewLearning unfamiliar platforms

Much of this was new ground: app stores, signing, release processes. I am comfortable learning unfamiliar platforms, and the AI is a patient guide, but a guide is not a certificate. When it matters, such as a policy or a deadline, I check the official source myself, and I use scripts and the Play developer API to reduce repetitive steps.

Lessons so far

Glossary
Offline-first
An app that works fully without an internet connection.
Specification
A written description of what to build, before building it.
Unit test
A small automated check of one piece of code.
Signing
Marking an app release as coming from you, so it can be verified.
Release track
A stage in Google Play, such as testing or production, where a version is published.
Agent
AI that works through several steps toward a goal using tools.

Frequently asked questions

Are the apps on Google Play?

They are being prepared for Google Play. Until a store button appears on the apps page, they are not yet live there.

Do you write any code yourself?

I direct the product, review quality and run the release process. The AI writes much of the code, under my specification and review.

Why no cloud sync?

To keep things simple and private. The trade-off is that you manage your own backups.

Key takeaways
