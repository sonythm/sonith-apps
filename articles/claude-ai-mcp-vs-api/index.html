MCP vs API: what is the difference, and when do you need which

A picture-led comparison of the Model Context Protocol and ordinary APIs: who calls whom, how tools are discovered, why they are partners rather than rivals, the security picture, and how to try an MCP server safely in Claude Code.

Reading level

You will hear two similar-sounding terms around AI tools: MCP and API. People often ask which one to use, as if they were competitors. They are not. This article draws the difference, shows how they fit together, and ends with one safe first step you can try. Facts come from the official MCP documentation and Claude Code documentation, checked on 2026-10-21 and listed at the end. Where something is my own view or analogy, it is labelled.

In plain words

An API (application programming interface) is a way for one piece of software to ask another to do something, using agreed rules. MCP (Model Context Protocol) is an agreed set of rules specifically for connecting an AI application to outside tools and data. Most MCP servers sit in front of ordinary APIs.

The USB-C idea

The official MCP introduction describes MCP as an open-source standard for connecting AI applications to external systems, and offers a comparison: think of MCP like a USB-C port for AI applications. Just as USB-C gives electronic devices one standard way to connect, MCP gives AI applications one standard way to reach files, databases, search engines and other tools.

The waiter and the menu

My view and analogy (not from the specification)

My own analogy, not from the specification. An API is like the menu of one particular kitchen: it lists exactly what that kitchen can make and how to order it, and every kitchen words its menu differently. MCP is like a standard way for a waiter to ask any kitchen "what can you make today?" and then place an order in a common format. The kitchen still cooks with its own menu behind the scenes.

Who is the caller, and how are tools found

With a normal API, a developer reads the documentation, writes code that calls specific addresses, and hard-codes the details. With MCP, an AI application connects to a server and asks it what it offers, and the model decides during the conversation whether to use something.

Proven foundation

In MCP, servers can offer three kinds of thing: tools (functions the AI application can invoke), resources (data that gives context, such as file contents or records) and prompts (reusable templates). Clients discover them with list requests, for example a tools list, and then use them. The tool list is described as dynamic, so a server can change what it offers. Source: the MCP architecture overview.

One request in each world

Partners, not rivals

My view and analogy (not from the specification)

My reading of the official architecture page: its examples of what tools can do include file operations, API calls and database queries, so an MCP server often calls an existing API. That is why I describe MCP as a layer for AI applications rather than a replacement for APIs. Not every server wraps an API; some read local files directly.

Why a shared standard helps, as simple arithmetic:

The official introduction summarises the benefit as "build once and integrate everywhere". The numbers above only show the shape of the idea.

Safety: the part not to skip

Proven foundation

The MCP specification says there should always be a human in the loop with the ability to deny tool invocations, that applications should make clear which tools are exposed and show when they are invoked, and that clients must treat tool annotations as untrusted unless they come from trusted servers. Claude Code's documentation says to verify you trust each server before connecting it, and warns that servers that fetch external content can expose you to prompt injection risk. Anthropic reviews connectors it lists in its directory but does not security-audit or manage any MCP server.

Careful

A local MCP server runs on your machine with the same privileges as the application that starts it. The official security guidance lists arbitrary code execution and data loss among the risks, so prefer servers you wrote or providers you trust, and read the exact command before you approve it.

Which should I use?

Try it: one safe first step

Key idea

This uses only commands from the Claude Code documentation. In a terminal, run claude mcp list to see what is connected (probably nothing). Choose one server from a provider you trust, and add it with claude mcp add --transport http NAME URL for a remote server, or claude mcp add NAME -- COMMAND for a local one, replacing the placeholders with the values in that provider's instructions. Inside a Claude Code session, type /mcp to check its status and sign in. By default, a server is added for you alone and for the current project (local scope), so it does not affect teammates. Start by asking Claude to only read, not change, anything.

Expert viewHow the messages work

MCP uses JSON-RPC 2.0 for its messages, in two layers: a data layer that defines the messages and primitives, and a transport layer that carries them. The standard transports are stdio (a client-launched subprocess, usually serving one client) and Streamable HTTP (HTTP POST with optional streaming, usually serving many). Claude Code's documentation marks the older SSE transport as deprecated. A client lists tools with a tools list request and runs one with a tools call request. In the current revision (2026-07-28), the protocol is stateless: each request carries the protocol version and capabilities, and a discover request lets a client learn a server's capabilities before anything else. Earlier revisions used an initialize handshake, so older servers behave differently.

Expert viewSign-in and remote servers

Authorization is optional in MCP. For HTTP-based transports, the specification describes an OAuth 2.1 based flow, with the server acting as a resource server, and it says to use scopes that follow least privilege. For stdio servers, it says implementations should not follow that flow and should retrieve credentials from the environment instead. In Claude Code, you complete a remote server's sign-in with the /mcp command, and the documentation says tokens are stored securely and refreshed automatically.

Expert viewContext cost and scale

Every tool definition takes space in the model's context. Claude Code's documentation says tool search is enabled by default for MCP tools: only tool names and server instructions load at session start, and full definitions are fetched when Claude needs them, so extra servers have minimal effect on context. Skills follow a similar load-on-demand idea; see Skills explained and Context explained. Tool output size is also limited: Claude Code warns when an MCP tool result exceeds 10,000 tokens and caps it at 25,000 by default.

Expert viewTrust, supply chain and sharing

A local server is a program you download and run, so it carries ordinary software supply-chain risks: a malicious startup command, a malicious package, or an insecure local service. The official guidance recommends consent dialogs that show the exact command, sandboxing and minimal privileges, and for servers meant to run locally, the stdio transport so only the client can reach them. In Claude Code, servers can be saved at local, project or user scope; project scope writes a .mcp.json file that can be shared through version control, and Claude Code asks for approval before using project-scoped servers. For team use, see Reuse context and share it with your team.

An API is the doorway to one building. MCP is a standard way for an AI to knock on any door.

Glossary
API
A set of rules that lets one program ask another to do something.
MCP
Model Context Protocol, an open standard for connecting AI applications to external systems.
MCP host
The AI application, such as Claude Code, that manages connections.
MCP client
The part of the host that keeps one connection to one server.
MCP server
A program that offers tools, resources and prompts to clients.
Tool
A function an AI application can invoke through a server.
Resource
Data a server offers as context.
Prompt injection
Hidden instructions in content that try to steer the model.
Least privilege
Giving only the access that is needed.

Frequently asked questions

Does MCP replace APIs?

No. MCP is a standard way for AI applications to connect, and many servers call ordinary APIs behind the scenes.

Do I need MCP to use Claude?

No. Claude works without it. MCP is for connecting Claude to your own tools and data.

Is every MCP server safe?

No. Treat each server like software you are choosing to trust, and review what it can do.

Is this the same as Skills?

No. Skills package instructions and know-how for Claude; MCP connects Claude to outside systems. They can be used together.
