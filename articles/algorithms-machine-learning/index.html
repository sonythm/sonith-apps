How machine learning algorithms learn

Learning from examples instead of fixed rules, gradient descent as walking downhill, decision trees, neural networks, overfitting, and how this connects to language models.

Reading level

Most algorithms in this series follow rules a person wrote down. Machine learning flips that: instead of writing the rules, you show a program many examples and let it adjust itself until it gets them right. This part explains how that adjustment works, using hills, questions and dials. It is a general overview, not a guide to any specific tool. Each section has a plain layer and an Expert view.

Learning from examples

There are two phases. In training, the model adjusts itself using example data. In using (also called inference), the finished model makes predictions on new inputs without changing.

In plain words

Think of learning to throw darts. You throw, see how far you missed, and adjust your aim a little. Training is thousands of throws. Using the model is the moment you throw for real.

Error as a hill, learning as walking downhill

In plain words

Every model has settings that can be changed. For each combination of settings, you can measure how wrong the model is on the examples. That wrongness is called the loss. Picture it as the height of a landscape: high ground is bad, the lowest valley is best. Learning is walking downhill in fog: you cannot see the valley, but you can feel which way the ground slopes and step that way.

The method is called gradient descent. At each step the program works out the slope of the loss at the current settings and moves a little in the downhill direction. The size of each move is the learning rate.

Expert viewThe update rule

In words: new value = old value minus step size times slope. The slope (the gradient, when there are many settings) points uphill, so subtracting it moves downhill. A tiny step size is safe but slow; a large one can overshoot, bounce, or even diverge. Real loss landscapes have millions of dimensions, plateaus and many valleys, and gradient descent usually finds a good valley, not provably the best one.

Computing the slope on all the data at every step is expensive, so stochastic and mini-batch versions estimate it from one example or a small random batch. The estimate is noisy but cheap, and the noise can even help. Many practical variants adapt the step size during training.

Decision trees: twenty questions

In plain words

In the game of twenty questions, each answer narrows the possibilities. A decision tree is a set of yes or no questions, arranged as a tree (see the previous part), that ends in an answer. Training chooses which question to ask at each branch.

Expert viewHow trees are learned

Training builds the tree greedily: at each node, try candidate questions about the features and keep the one that best separates the example labels, using a measure of how mixed the groups remain (for example Gini impurity or entropy). Stop at a depth limit or when groups are pure. A single deep tree tends to memorise its training data, so practical use often combines many trees, for example by averaging many trees trained on different random samples. Trees are easy to explain, which is a real advantage.

Neural networks: many tiny dials

In plain words

Imagine a wall of dials arranged in layers. Numbers go in at the left, each dial scales and combines what it receives, and a final answer comes out at the right. Training turns the dials a little at a time, using the downhill walk above, until the answers improve.

Expert viewBackpropagation in one paragraph

Each connection has a weight, and each unit applies a simple non-linear function so that stacking layers can represent complicated patterns. Training repeats: run an example forward to get a prediction, measure the loss, then use backpropagation to work backwards through the layers and compute how much each weight contributed to the loss. This uses the chain rule of calculus to reuse work, so the full set of slopes costs about as much as one forward pass. Gradient descent then nudges every weight a small step downhill.

Overfitting and underfitting

In plain words

A student who memorises last year's exam answers will do well on that exam and badly on a new one. A good model learns the idea, not the answer sheet.

The standard defence is a train/test split: keep some data hidden during training, then measure performance on it. If training results are far better than test results, the model is overfitting.

Expert viewRegularisation and evaluation

Regularisation discourages over-complex models, for example by penalising large weights, limiting tree depth, or stopping training when error on held-out data starts rising. A separate validation set is used to tune choices, leaving the test set for one final check.

Accuracy can mislead on imbalanced data: if 1 percent of cases are positive, a model that always says "negative" is 99 percent accurate and useless. Precision asks: of the items the model flagged, how many were truly positive? Recall asks: of all the truly positive items, how many did the model find? There is usually a trade-off between them.

Data quality matters as much as the algorithm. Leakage happens when information from the answer, or from the test data, sneaks into training, giving flattering results that vanish in real use.

Two main kinds of learning

Connection to language models

A language model such as Claude is, in general terms, a very large neural network trained to predict the next piece of text given the text so far. Repeating that prediction one piece at a time produces whole replies. The ideas in this article (examples, loss, gradient descent, held-out testing) are the same family of ideas, applied at far greater scale.

Careful

Models learn patterns from data, so they can be wrong, including sounding confident while wrong. Check important results. I am not describing the size, training data or abilities of any particular model here.

To learn how to work with one in practice, see the Claude AI series and start with What is Claude AI?.

Glossary
Training
Adjusting a model's settings using example data.
Loss
A number measuring how wrong the model is.
Gradient descent
Repeatedly stepping the settings in the direction that lowers the loss.
Learning rate
The size of each step.
Overfitting
Fitting the training data so closely that new data is handled badly.
Weight
An adjustable number inside a model.
Label
The correct answer attached to a training example.
Precision and recall
How many flagged items were right, and how many true items were found.

Frequently asked questions

Does the model understand what it learns?

It captures statistical patterns that help it predict. Whether to call that understanding is debated, so rely on testing, not assumptions.

Why not always use the biggest model?

Larger models cost more to train and run, need more data, and can still overfit or be wrong.

What is the difference between training and inference?

Training changes the model's settings; inference uses the finished model without changing it.

Why hold back test data?

To measure how the model does on cases it has never seen, which is what matters in use.
