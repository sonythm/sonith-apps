Reading level

Chat answers a question. An agent does a job. Claude Code is Anthropic's agent for software work, and it changes how people build apps. This closing part of the series explains what it does in plain language, how the pieces from earlier parts (context, CLAUDE.md, skills) fit together, and how to keep control while it works. Written for builders and curious beginners alike.

What is Claude Code?

Anthropic describes Claude Code as an agentic coding tool that reads your codebase, edits files, runs commands and integrates with your development tools. A codebase is the folder of files that make up a piece of software.

Most of these need a Claude subscription or an Anthropic Console account. You describe what you want in plain language; Claude Code plans the approach, writes code across several files and verifies that it works. For a bug, paste the error and it traces the cause.

Expert viewSurfaces share one engine

Anthropic's overview says each surface connects to the same underlying Claude Code engine, so your repository's CLAUDE.md files, settings and MCP servers work across all of them. Sessions are not tied to one surface: you can move work between them, for example start on the web and pull it into your terminal, and the docs describe Remote Control for continuing a session from a phone or another browser.

The agent loop

A good agent reads the relevant files, makes a plan, changes things, then checks the result, for example by running the tests. If the check fails it goes round again. That loop is why agents finish bigger jobs than a single chat answer, and why review matters more: more happens between your request and the result.

In plain words

Chat is like asking a colleague a question. An agent is like handing them a task and a key to the office. You want to know what they did with the key.

How the earlier pieces fit together

Expert viewContext cost by feature

Anthropic's extension guide gives the loading rules: CLAUDE.md loads in full each session; skills load descriptions at start and bodies when used; MCP loads tool names with schemas on demand; subagents get a fresh, isolated context and return a summary; hooks cost nothing unless they return output. It adds practical advice: use a subagent when a side task would flood your conversation with output you will not reuse, write a hook when you want something to happen every time without asking, and capture a playbook as a skill the third time you paste it into chat.

New to MCP? MCP vs API explains how it differs from an ordinary API and how to try a server safely.

Permissions: your safety rail

Claude Code uses a tiered permission system, according to Anthropic's documentation.

Kind of actionExampleAsks first (default manual mode)?
Read-onlyFile reads, searchingNo, inside your project
Shell commandsRunning a build or testYes, apart from a built-in set of read-only commands
Editing filesWriting or changing a fileYes
Fetching the webReading a pageYes, apart from a set of pre-approved documentation sites

When it asks, the prompt shows what Claude is about to do, and one of your options is "yes, and don't ask again" for that kind of action. You can also write allow and deny rules and share them with your team.

Every approval you grant widens what the agent can do on its own. Widen it slowly, for tasks and places you trust.

Expert viewEnforcement versus instructions

Anthropic's documentation describes permission modes that change what asks and what does not, and says in the memory and extension guides that CLAUDE.md is context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook. A hook that rejects an unsafe command is enforcement; an instruction saying "never do that" is a request. Also treat any external content (web pages, files from unknown sources, tool results) as potentially hostile: text inside it can try to steer an agent, called prompt injection. Anthropic says Opus 5.5 is more resistant to it than its predecessor, which is progress, not a guarantee.

A safe working routine

Building by describing and accepting without reading is often called vibe coding; Vibe coding explained covers where it works and the checks that keep it safe.

Careful

Do not give an agent permission to run commands you do not understand, on a machine that holds things you cannot afford to lose.

Prompts that work well with an agent

Text
Goal: add a "mark as paid" button to the invoice screen.
Constraints: follow the existing code style; do not change the database format.
First, read the relevant files and tell me your plan. Wait for my OK.
After the change, run the tests and tell me what you checked.
Expert viewGoing further

Beyond interactive use, Anthropic's documentation shows Claude Code driven from scripts and CI: piping logs into it, running it non-interactively with claude -p, and using GitHub Actions or GitLab CI/CD for code review and issue triage. It also describes an Agent SDK for building your own agents powered by Claude Code's tools, with full control over orchestration, tool access and permissions, and dynamic workflows that run many subagents from a script Claude writes. Free self-paced courses are available at Claude Academy.

Glossary
Agent
Claude working in a loop with tools toward a goal.
Codebase
The collection of files that make up a software project.
Diff
A view of exactly what changed in the files.
Pull request
A proposed change that others review before it is merged.
MCP
Model Context Protocol, a standard for connecting AI tools to other software and data.
Hook
A command that runs automatically on an event, with no model judgement involved.
Subagent
An isolated worker with its own context window that returns a summary.
Prompt injection
Hidden instructions in content that try to steer an AI agent.

Frequently asked questions

Do I need to be a programmer to use Claude Code?

It helps. You do not need to write every line, but you need to read and judge the result, or have someone who can.

Can it break my project?

Any tool that edits files can. Version control and review are your protection.

Is it only for code?

It is designed for software work. The idea of an agent with tools reaches beyond it.
